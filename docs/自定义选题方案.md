# 自定义选题方案（供小组讨论）

## 一、基线现状分析

当前仓库基线为 xv6-riscv 官方最新版（2026-09-01 拉取），关键现状：

**已具备的功能：**
- 默认 RR 轮转调度（`proc.c`）
- lazy allocation 延迟分配（`vm.c`）
- 22 个基础系统调用（fork/exec/wait/pipe/open/...）
- `printk`、`pause`、`sync`、`logstress` 等新特性

**尚未实现（可作为扩展点）：**
- 写时复制 COW
- mmap 内存映射
- 资源限制 / 优先级调度
- 系统调用审计与追踪
- slab / 伙伴内存分配器

## 候选一：写时复制 fork（COW）+ 内存共享统计

### 难度：⭐⭐⭐（与 MLFQ 选题相当）

### 课题简介

xv6 原生 fork 会把父进程的全部物理内存复制一份，开销大且浪费内存。
本课题实现写时复制（Copy-on-Write）：fork 时只复制页表，物理页共享并标记只读；
任一进程写共享页时触发缺页异常，内核在 trap 处理中为该页复制独立物理页。

### 核心功能需求

- 物理页引用计数（`kalloc.c` 扩展）
- fork 只复制页表 + 共享页标记只读（`proc.c`）
- 缺页异常处理 COW 页复制（`trap.c`）
- 共享页解除映射时按引用计数决定是否真正释放（`vm.c`）
- 新增系统调用 `getmeminfo`：查询进程共享页 / 独占页 / 总内存占用
- 用户态测试程序：验证 COW 正确性 + 统计内存数据

### 改动文件

`kernel/vm.c`、`kernel/kalloc.c`、`kernel/trap.c`、`kernel/proc.c`、`kernel/proc.h`、`kernel/sysproc.c`、`user/`

### 对比实验

- fork N 次总耗时：COW vs 全复制
- 同一多进程场景内存占用对比
- 共享页数量随 fork/exit 的变化曲线

### 适配优势

MIT 6.S081 标准 lab，实现思路成熟、考核认可度高；覆盖虚拟内存 + 异常处理
两大核心知识点，答辩有深度。

## 候选二：mmap 内存映射文件

### 难度：⭐⭐⭐（与 MLFQ 选题相当）

### 课题简介

xv6 原生只有 read/write 系统调用方式读写文件。本课题实现 `mmap`/`munmap`
系统调用，用户程序可将文件映射进地址空间，通过内存读写直接访问文件内容；
缺页时由内核惰性加载数据页（复用已有 lazy 机制），支持私有/共享两种映射。

### 核心功能需求

- 进程 VMA（虚拟内存区域）结构体（`proc.h`）
- `mmap` 系统调用：建立文件与地址空间的映射（`sysfile.c`、`vm.c`）
- `munmap` 系统调用：解除映射并回写脏页（私有映射）或丢弃（共享映射）
- 缺页惰性加载映射页（`trap.c`）
- 用户态测试：mmap 读写文件、映射大文件、共享映射多进程交互
- 新增系统调用 `mmap`/`munmap`（2 个）

### 改动文件

`kernel/proc.h`、`kernel/vm.c`、`kernel/sysfile.c`、`kernel/trap.c`、`kernel/defs.h`、`user/`

### 对比实验

- mmap 读写 vs read/write 系统调用的吞吐量对比
- 不同映射文件大小的缺页率变化
- 共享映射下多进程数据一致性验证

### 适配优势

实用性强，对照 Linux mmap 讲原理；与基线已有 lazy 机制天然衔接，
实现有据可依，不易跑偏。

## 候选三：系统调用追踪与性能剖析器（strace + profiler）

### 难度：⭐⭐⭐（与 IPC+信号选题相当）

### 课题简介

xv6 原生没有系统调用观测手段。本课题实现一个类 Linux `strace` + `perf`
的内核观测工具：审计每个进程的系统调用序列，同时通过时钟中断采样用户态
PC，输出进程热点函数分布，帮助分析和优化用户程序。

### 核心功能需求

- 内核审计模块：记录进程每次系统调用的编号、时间戳（`syscall.c`）
- 时钟中断采样：周期性记录用户态 PC 到每进程直方图（`trap.c`）
- 新增 4 个系统调用：
  - `trace_on` / `trace_off`：开启/关闭某进程的调用追踪
  - `prof_start` / `prof_stop` / `prof_result`：性能采样与结果读取
- 用户态 `strace` 工具：打印程序系统调用序列
- 用户态 `prof` 工具：输出热点占比（直方图/柱状图）
- 测试程序：CPU 密集 vs IO 密集两类负载，对比热点分布差异

### 改动文件

`kernel/syscall.c`、`kernel/trap.c`、`kernel/proc.h`、`kernel/proc.c`、
`kernel/sysproc.c`、`user/`（新增 strace、prof、测试程序）

### 对比实验

- CPU 密集 / IO 密集 / 混合负载下的热点分布对比
- 追踪开启 vs 关闭的性能开销对比
- 不同程序系统调用频率分布统计

### 适配优势

**创新性最高**，完全区别于老师 4 个参考选题；贴合"网络空间安全"专业背景
（审计是安全领域核心概念）；答辩演示效果直观，易出彩。

## 三、3 周进度规划建议（任一候选通用）

### 第 1 周：方案设计与框架

- 全体成员通读对应模块源码（vm/proc/trap）
- 确定数据结构与接口规范（结构体定义、系统调用约定）
- 完成各成员模块框架搭建

### 第 2 周：并行开发与联调

- 各成员独立实现核心功能，每日自测
- 周末合并代码，解决模块冲突，完成功能联调

### 第 3 周：测试优化与结题

- 全量功能测试、边界用例、性能数据采集
- 运行截图、测试日志整理
- 课程设计报告、答辩 PPT

## 四、4 人分工模板（以候选三为例）

| 成员 | 职责 |
|---|---|
| 组员 1 | 内核审计模块、系统调用入口实现 |
| 组员 2 | 时钟采样模块、PC 直方图维护 |
| 组员 3 | 用户态 strace / prof 工具开发 |
| 组员 4 | 测试程序、数据采集、对比分析、报告 PPT |
